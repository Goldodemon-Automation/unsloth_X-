# Release v1.4.0 — the fork gets a mark, and the machine gets looked after

Two things at once: the fork now has a logo and a stated colour identity, and the wave behind it
closes the security, startup and load-path gaps the previous round left open.

## The mark: X in blue, – in lighter blue

The fork's identity in one glyph: an **X** in blue (`#2563EB`, deep `#1D4ED8`), a **–** in a lighter
blue (`#7DD3FC`), apart from it. Four constructions, because one file cannot serve a header and a
16-pixel tab icon:

| File | Where it belongs |
| --- | --- |
| `images/logo-x-minus.svg` | horizontal, two inks — README headers, splash screens |
| `images/logo-x-minus-badge.svg` | app icon on a dark plate — favicon, desktop icon, store listing, avatar |
| `images/logo-x-minus-stacked.svg` | X above the dash — the tight square that still reads at 16px |
| `images/logo-x-minus-mono.svg` | one ink, `currentColor` — inline it to inherit the theme |

`images/logo-options.html` shows all four side by side, on light and dark, at the sizes they are meant
for, with the palette. Pick there.

**The colour story, stated plainly:** upstream Unsloth is green (`#17b88b`); this fork is **blue** —
the UI accent moved to a light blue (`#9ceaf0`, a light cyan) in both modes, with dark ink on it
because white on that accent scores about 1.3:1. A screenshot that is still green is upstream's theme.

## Security: three gaps closed, three named

A read-only audit of the auth stack, the request surface, path and command handling, secret storage and
the desktop shell produced six findings. Three were fixed here and three are recorded with the reason
they are not one-line edits.

Fixed:

- **CORS could combine a wildcard origin with credentials.** Starlette answers that pair by reflecting
  the request's `Origin` and adding `Access-Control-Allow-Credentials: true`, so any page the user had
  open could make credentialed calls to the loopback backend and read the responses. Nothing here
  authenticates by cookie, so the flag is now `False`.
- **Two credential checks had no failure accounting.** `/api/auth/refresh` and
  `/api/auth/change-password` both answer differently depending on whether a secret was right, and
  neither counted wrong answers — on change-password that turned a 60-minute token into a password
  oracle. They now share a bounded limiter (10 failures in 60 s → 60 s), with the same 429 shape the
  sign-in path already used. The sign-in limiter itself was left alone: it is richer (per-account and
  per-IP) and stacking a second one on it would lock innocent usernames sharing an address.
- **The preview page and the desktop webview.** The public preview page was served with
  `script-src 'unsafe-inline'` on the same origin as the session tokens; its one inline block now
  carries a per-response nonce. The Tauri CSP gained `base-uri 'none'; object-src 'none'` — `base-uri`
  does not inherit from `default-src`, and one injected `<base>` tag could re-point every relative URL
  in a webview that exposes the whole IPC surface.

Recorded, not fixed: a session bearer accepted in `?token=` query strings (needs a scoped link, not a
one-line change), the missing host allow-list, and the trust-model difference between the two client-IP
resolvers.

## Speed: startup, browsing, Intel CPUs, Intel iGPUs

- **Startup.** `import main` cost 2.62 s here, most of it in route modules importing SDKs only some of
  their endpoints use. Those imports now happen inside those endpoints, with a source-level guard so a
  new module-scope import fails a test rather than quietly returning to the critical path.
- **Model browsing.** `utils/stat_signature.py` fingerprints a tree by `(path, size, mtime_ns)` without
  reading one byte of content, bounded at 2048 entries so the fingerprint cannot become the walk it
  exists to avoid; the cache inventory keys its answer on `(root, signature)` with a 60 s TTL and an
  explicit `invalidate()`. Two identical calls now walk once.
- **Intel CPUs.** bf16 is used on CPUs that actually have it — AMX-BF16 (Sapphire Rapids and newer) and
  AVX512-BF16 beside AVX512F (Cooper Lake / Ice Lake) — instead of a blanket "CPUs emulate bf16" rule
  that forced fp32 everywhere. The probe reads `/proc/cpuinfo` and answers "unmeasurable", not
  "absent", on Windows and macOS.
- **Intel iGPUs.** `utils/hardware/xpu.py` answers which PyTorch build is installed and what that means
  in one sentence, and pins `ONEAPI_DEVICE_SELECTOR=level_zero:N` for hybrid machines. `docs/igpu.md`
  is the page that did not exist: the wheel, the pin, and a symptom-first troubleshooting table.

## Verification

```bash
cd studio/backend
python -m pytest tests/test_lazy_route_imports.py tests/test_stat_signature.py \
  tests/test_cache_inventory_caching.py tests/test_xpu.py tests/test_auth_rate_limit.py \
  tests/test_security_hardening.py tests/test_cpu_tuning.py tests/test_desktop_auth.py -q

cd ../frontend && npm run typecheck && npm run build
```

125 tests across the touched suites in the round that added the limiter and the desktop-auth guard,
plus 23 for the CPU planner and 20 for the XPU probe; the frontend typecheck and build stay green.
