# Release v1.2.2 — the review fixes

A second, code-level review of the CPU / iGPU / NPU work found eleven defects. Three of them meant a
run could train on a device other than the one the user picked, or be sized against memory it would
never get. All are fixed here, with tests.

## What was wrong, and what it is now

**The pin only reached half the program.** `UNSLOTH_TRAINING_DEVICE` was read by `unsloth`'s own
device module but not by the Studio's hardware probe, so a GPU host pinned to the CPU still reported
CUDA to `cpu_training_host()` and the loader. `utils/hardware/hardware.py` now honours the pin (with
the reason token `pinned_to_cpu`, so the sidebar does not offer to "fix" a decision the user made),
and on Apple Silicon the pin also outranks MLX — selecting the CPU there used to train on the GPU
silently.

**An unreadable GPU could be reported as usable.** If torch answered for device 0 and then raised, the
probe kept the devices it had already read and the row stayed `supported`, with a device string that
fell through to `cpu`. The fit check would then size a 24 GB card that could not be read. A partial
read now yields no GPU rows at all, and `supported` additionally requires torch to name a backend.

**An Intel discrete card claimed to be unified-memory.** The `torch.xpu` branch hardcoded
`unified: true`, so an Arc A770 reported shared memory while the same payload's note said it had its
own. `unified` now follows whether the part is actually integrated.

**A CPU was budgeted against installed RAM, and described as a GPU.** The registry's CPU row carried
the total, and `budget_report` had no CPU arm, so the sentence read "This GPU has 15.4 GB of its own
memory" for a CPU. The row now carries *free* RAM, and the report says what it is.

**The polled route re-probed the whole machine every time.** One `GET /api/compute/targets` ran a
torch device probe, two psutil reads, two NPU detections and six runtime PATH scans (~30 ms here).
The probe and the capability are now cached for the same minute the hardware inventory uses, a
`POST` invalidates them, and the docstring no longer claims the module never reaches torch — it does,
through the probe, which is the point.

**Writing the target was not owner-gated.** `POST /api/compute/target` stored an installation-wide
setting behind a plain authenticated subject, while every neighbouring settings write requires the
owner. It requires the owner now.

**A missing module could 500 the route.** The registry imported `accelerator_budget` unguarded inside
`list_training_targets`, so a partial install raised straight out of a polled GET. It falls back to
the carve-out.

**An integrated-GPU pin could abort a run.** `UNSLOTH_TRAINING_DEVICE=igpu` resolves by *raising* when
no integrated backend answers, so a run whose child lost the GPU died in the loader instead of
reporting the device it used. The pin is gone for `igpu` — the card is already selected through
`CUDA_VISIBLE_DEVICES`/`ZE_AFFINITY_MASK`, and the shared-memory flags are the part the run needs.

**Two integrated GPUs disagreed about the budget.** `carveout_bytes` took the first integrated card
while the target's own row took the resolved one; with a 0.5 GB and a 2 GB part the two figures
differed by tens of GB. It now takes the resolved index.

**The NPU refusal tokens were incomplete.** `no_backward_pass`, `npu_is_primary` and `not_measured`
were reachable but absent from the module's published list, and `REFUSAL_TOKENS` now names all of
them, so a UI translating them cannot fall through to snake_case.

**The inference backend still spoke AMD-only.** It used `detect_amd_npu()`, so an Intel, Qualcomm or
Apple NPU that the Studio reported never reached inference. It now prefers `detect_npu()` and keeps the
AMD path as the fallback, and every internal device entry has the same shape.

## Limits, stated

- The catalogue is unchanged: an NPU still cannot run a backward pass.
- The cache means a device attached in the last minute may not appear until it expires; the `POST`
  path and the hardware inventory's own 60-second refresh bound that.
- Nothing here changes what a discrete-GPU run does.
